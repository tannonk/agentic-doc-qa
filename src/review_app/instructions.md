## Q&A Annotation Guidelines 

These guidelines are intended to facilitate the human-in-the-loop annotation of automatically-generated Q&A pairs. 

### Q&A Generation and Validation Process

Q&A pairs are generated through a multi-step process involving both automated and human validation. For a given PDF source document, the process is as follows:

1. Pages are randomly sampled from the PDF and converted to page images.
2. A page image is presented to an multi-model LLM along with a detailed prompt, instructing the LLM to generate a set of Q&A pairs based on the content of the page image.
3. The generated Q&A pairs are then validated by a judge LLM, which checks for question and answer validity against the page source.
4. LLM-judge feedback is provided to the Q&A-generating LLM, which may result in the generation of additional Q&A pairs.
5. Once a minimum number of valid Q&A pairs is generated, the validated Q&A pairs are saved to disk for human review.

### Human Review of Q&A Pairs

The human review process is designed to ensure the quality and accuracy of the Q&A pairs generated by the LLM as described above. 

The human reviewer is presented with a single Q&A pair at a time, along with the corresponding page image from which the Q&A pair was generated. 

The reviewer is asked to `approve`, `reject`, or `edit` the Q&A pair based on the following criteria:

**When to approve?**

- The question and answer are both accurate and well-formed, given the content of the source document.
- The question reflects a realistic question that a human might ask about the content of the page image.

**When to reject/edit?**

- The question or answer is incorrect given the content of the source document.
- The question is not answerable given the content of the source document.
- The question is not well-formed or is ambiguous.
- The question is not specific enough to the content of the source document.
- The question references visual elements in the page image that make it unrealistic to be asked by a user (e.g. "according to the figure", "on the left of the slide", etc.).
- The source document is no longer available, making it impossible to validate the Q&A pair.

**When to edit?**

- The question or answer is potentially interesting and only needs slight modifications to be considered accurate and well-formed, given the content of the source document.

Obviously, editing takes considerably more time than simply approving or rejecting a Q&A pair. We aim to generate a large enough pool of Q&A pairs to ensure that the final dataset is of high quality, despite discarding some pairs. It is up to the reviewer's discretion to determine whether a Q&A pair should be rejected or edited, based on the criteria above.

### Problematic Questions - either `reject` or `edit`

| Question | Reason for rejection/editing |
| --- | --- |
| "Which two therapy sub‑areas are listed in the yellow circle, and which one includes 'host response'?" | "the yellow circle" references a visual element in the page image, making it unrealistic to be asked by a user |
| "Welches übergeordnete Ziel verfolgt die in der Überschrift genannte Stadt‑weite Transmissionsstudie?" | "in der Überschrift genannte" - as above |
| "According to the WHO definition shown on the slide, which three symptoms or criteria must be present for a case to be classified as ILI?" | "shown on the slide" references a specific page |


### Navigation

- The reviewer page includes navigation buttons and a slider to facilitate moving between Q&A pairs. The reviewer can also skip a Q&A pair if the source document is no longer available.

- Keyboard shortcuts can be used to approve, reject, or edit a Q&A pair, as well as to navigate between pairs. The available keyboard shortcuts are displayed on the relevant buttons in the reviewer interface.

- Use the zoom bar to zoom in/out of the page image. The zoom level is preserved when navigating between Q&A pairs.
